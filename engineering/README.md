# ⚙️ 工程质量

工程实践类 skill，涵盖测试策略、调试方法、代码审查、部署运维、异步编程、错误处理。

## Skill 清单

### `test-driven-development`

TDD 红-绿-重构循环：编写测试 → 看到失败 → 最小实现 → 重构。适用于任何功能或 bugfix。

> **场景示例：** 用户说“实现一个邮箱格式校验函数” → 先写测试用例（空字符串、缺 @、缺域名、正常邮箱），每个测试先红后绿，最后重构校验正则。

### `systematic-debugging`

系统化调试四阶段法：复现 → 定位根因 → 修复 → 验证。遇到任何 bug 或测试失败时先走这个流程。

> **场景示例：** 用户反馈“列表页面偶尔白屏” → 不猜测不跳步，先加防御性日志复现，二分注释定位到某个数据为 undefined 的渲染，修复后验证所有边界情况。

### `verification-before-completion`

完成前自检：在声称“完成了”“修好了”之前，必须实际运行验证命令并确认输出，先有证据再断言。

> **场景示例：** 改完一个表单校验逻辑准备说“搞定了” → 先运行 `pnpm dev` 打开浏览器，手动输入边界值确认校验生效，截图留证后再提交。

### `deploy-to-ecs`

将项目部署到阿里云 ECS：配置 Nginx、上传构建产物、启动服务、域名绑定。

> **场景示例：** 前端项目开发完成，需要上线到测试服务器 → 自动打包构建产物，SSH 上传到 ECS，配置 Nginx 反向代理和 HTTPS，确认网页可访问。

### `webapp-testing`

Playwright 前端自动化测试：验证 UI 功能、调试交互行为、浏览器截图、查看日志。

> **场景示例：** 写完一个注册流程（3 个步骤的表单）→ 用 Playwright 脚本自动填写三步表单、提交、验证成功跳转，并截图留存，确保流程不退化。

### `error-handling`

结构化错误处理：区分“给 LLM 看的错误”（文件未找到、网络超时）和“崩溃级错误”（认证失败、状态损坏）。

> **场景示例：** 写一个 API 请求工具函数 → 按此模式抛出类型化错误，让上层能区分网络错误（可重试）和业务错误（提示用户），而非一律 `throw new Error("出错了")`。

### `module-organisation`

按职责边界组织代码，非按功能：`tools/` 放能力、`commands/` 放命令、`services/` 放业务逻辑、`hooks/` 放状态订阅。

> **场景示例：** 项目从 3 个页面长到 15 个页面，目录开始混乱 → 按此模式重组：组件不直接调 API（抽到 services），组件不渲染 markdown（抽到 utils），每个模块边界清晰。

### `async-concurrency`

异步并发模式：只读工具并行执行、AbortController 传播取消、Promise.all 并行初始化。

> **场景示例：** 页面加载时需要同时请求用户信息、权限列表和配置数据 → 用 `Promise.all` 并行发起，用 `AbortController` 处理超时统一取消，而非串行等待。
